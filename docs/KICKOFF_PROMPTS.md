# Claude Code 作業指示書（フェーズ別プロンプト）

> 使い方：各フェーズの「プロンプト」をClaude Codeにそのまま貼り付ける。**1フェーズずつ**進め、完了したら `docs/WORKLOG.md` とスクリーンショットをPMに共有してレビューを受けてから次へ進む。
> 🔁 マークのフェーズは、最初に Plan Mode（`Shift+Tab` で切替）で計画を出させ、承認してから実装させる。

## Phase 2：土台づくり 🔁 ［Opus 5.5 → 定型部分は Sonnet 5.5］

```
docs/PLAN.md の Phase 2 を実装してください。範囲：

1. Next.js（App Router）+ TypeScript strict + Tailwind + next-intl（ja既定・en）のセットアップ
2. src/content/schema.ts：Layer / Metric / Evidence / Confidence（'measured' | 'approx' | 'reconstructed'）を zod で定義
3. src/content/layers.ja.ts / layers.en.ts：docs/BRIEF.md §4〜§6 から全地層のコンテンツを作成
   - 数値は §6 ファクトシートのものだけを使い、確度ラベルも §6 のとおりに付ける
   - 英語版は自然な英語に翻訳する（直訳しない）。専門用語は正確に
   - ビルド時に zod で検証し、不正があればビルドを失敗させる
4. 品質基盤：ESLint、typecheck、Playwright（デスクトップ／モバイル／reduced-motion）、Lighthouse CI（CLAUDE.md §4 の予算をアサーションに設定）
5. 3Dなしの「HTMLだけ版」で全地層を表示するページ（これが全フォールバックの土台になる）
6. docs/WORKLOG.md を作成して記録を開始

完了したら、HTMLだけ版のスクリーンショット（ja/en、デスクトップ/モバイル）と Lighthouse の結果を見せてください。
```

> 💡 3. のコンテンツ投入が長くなったら `/model sonnet` に切り替えてよい。終わったら `/model opus` に戻す。

## Phase 3：中核の仕組み 🔁 ［Opus 5.5／シェーダーのみ Fable 5.2］

```
docs/PLAN.md の Phase 3 を実装してください。サイトの「骨格」となる仕組みです：

1. three/Stage.tsx：単一の固定Canvas。現在の地層と前後1枚だけのシーンをマウントし、それ以外は破棄してGPUメモリを解放
2. three/quality.ts：detect-gpu と prefers-reduced-motion から high / medium / low / static の品質ティアを決定
3. lib/scroll：Lenis + GSAP ScrollTrigger を統合し、「現在の地層」「地層内の進捗（0〜1）」をグローバルな状態として提供
4. 深度計（現在の地層名と深さ）と「30秒で見る」ボタン
5. ボーリングコア・ナビゲーター（BRIEF §3）：通過した地層ごとに色のリングが積み重なる3D円柱。リングをクリックするとその地層へ移動。キーボードでも操作可能に
6. 根拠ドロワー（BRIEF §3）：Metric をクリックすると、測定方法・確度ラベル・図表を表示。フォーカス管理とEscで閉じる操作も実装

各シーンの中身はまだ仮の単純な図形で構いません。この段階で、スクロール・シーン切替・メモリ解放がモバイルで滑らかに動くことを検証し、fpsとGPUメモリの計測値を WORKLOG に残してください。
```

コアサンプルや地層の質感を独自のシェーダーで作る段階で：
```
/model fable
```
```
ボーリングコアと地層断面のマテリアルを独自のGLSLシェーダーで作ってください。
条件：堆積岩のような層の質感、地層ごとの色はデザイントークンから受け取る、通過した直後のリングが内側から淡く発光する、モバイル（quality=medium）でも30fps以上。
low ティア用に、テクスチャだけの軽量版も用意してください。
```
終わったら `/model opus` に戻す。

## Phase 5：各地層の実装 🔁 ［シーンごとにモデルを指定］

推奨する実装順（リスクの高いものから先に）：**5 オークション → 4 PHP診断 → 2 Genten → 6 特許 → 3 pegasus → 1 現在 → 7〜10**

各地層に共通して使うプロンプト（`<ID>` と `<名前>` を置き換える）：
```
ブランチ feat/layer-<ID> を作成し、docs/BRIEF.md §5 の「<名前>」の仕様を実装してください。

要件：
- コンテンツは src/content のデータから描画する（ハードコード禁止）
- 3D演出は quality ティアごとに段階を設け、static では静止画とHTMLだけで内容が伝わること
- すべての数値は Metric コンポーネント経由で表示し、根拠ドロワーとつなぐ
- インタラクションはキーボードでも操作できること
- CLAUDE.md §7 の完了の定義をすべて満たすこと

まず Plan Mode でシーンの演出計画（カメラの動き、スクロール進捗0〜1に対するタイムライン、インタラクション、品質ティアごとの差分）を提出してください。
```

地層ごとの補足指示（共通プロンプトの後ろに付け足す）：

**5 ライブオークション** ［Opus 5.5］
```
同時入札者数スライダーのシミュレーションは、BRIEF §6 の実測値（約6時間・約10,000件・エラー0件、8コア）と矛盾しない範囲で、見せ方のための模擬モデルとして作ってください。「インスタンスを闇雲に増やす」ボタンは押せない状態にし、「まず実測する」へ誘導してください。
```

**4 レガシーPHPセキュリティ診断** ［Opus 5.5。都市の描画最適化だけ Fable 5.2］
```
演出データはすべて模擬データで作り、画面に「再現」ラベルを常に表示してください。実際に悪用できるペイロードやコードは表示しないでください。
まず都市の描画（45,000インスタンス）を単体で作り、モバイルで30fps以上出ることを確認してから、ストーリー部分を実装してください。
```
都市の描画最適化をFableに任せる場合（セキュリティの文脈は含めずに依頼する）：
```
/model fable
```
```
InstancedMesh を使って約45,000棟の建物からなる都市を描画してください。建物の高さはデータ配列で与えます。カメラが特定の区画へ急降下する演出、特定のインスタンス群を脈打つように発光させる機能、LOD とフラスタムカリングによってモバイルで30fps以上を維持すること、が要件です。
```
終わったら `/model opus` に戻す。

## Phase 6：品質の仕上げ ［Opus 5.5 ＋ サブエージェント］

```
公開前の総点検を行ってください：
1. confidentiality-guard と perf-auditor のサブエージェントを実行し、指摘をすべて解消
2. 実機相当の条件（モバイルのCPU 4倍スロットリング＋4G相当）で全地層を通しでスクロールし、fpsの低下箇所を特定して改善
```
