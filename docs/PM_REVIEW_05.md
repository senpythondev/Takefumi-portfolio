## 3. 報告への回答

### 3.1 3Dを最初の操作で読み込む方式
- **承認。** 読み込み後に自動で始める方式だとTBTが約1.1秒になる。これは指標上の問題であると同時に、遅い端末の訪問者にとって実際に画面が固まる時間でもある。操作をきっかけにする方式のほうが誠実。
- 代償（操作するまでヒーローの3Dが出ない）への対策を **Phase 4 の要件**にする：
  - ヒーローは**3Dがなくても完成して見える**デザインにする。
  - 3Dの代わりに、ヒーローの3Dを Playwright で撮った**静止画（ポスター）**を最初から表示し、CSSだけでごく控えめに動かす（呼吸するような明暗。初期JSは増やさない）。3Dの準備ができたらクロスフェードで差し替える。
  - `prefers-reduced-motion` と static ティアでは、ポスターを動かさない。
- 指標を良く見せるためだけのタイマーによる遅延読み込み（数秒後に自動で読み込むなど）は**採らない**。

### 3.2 操作直後のブロック（4倍スロットリングで最大約200ms）
- 3-10 で削減に取り組む。候補：初期化を小さな単位に分けて間に制御を返す（`scheduler.yield` など）、シェーダーの事前コンパイル（`compileAsync`）を分割する、テクスチャの転送を分散する、最初のフレームでは現在の地層だけを用意する。
- 目標は、4倍スロットリングで、操作直後の Long Task が1回あたり100ms以下。

### 3.3 `/ja` の TBT（中央値197ms／上限200ms）
- 余裕がほとんどない。3-10 に「**`/ja` と `/en` の差の原因調査**」を加える（日本語のメッセージ量、ハイドレーションの範囲、フォントの処理など）。
- CI の値を正式とする方針は変えない。非公開化して CI が回ったら、その値を WORKLOG に記録すること。

### 3.4 `next/dynamic` ではなく `React.lazy`
- **承認。** 3Dの描画ツリーの中では `next/dynamic` が使えないため、妥当な判断。シーンごとに遅延読み込みのチャンクに分かれていることが本質であり、それは守られている。
