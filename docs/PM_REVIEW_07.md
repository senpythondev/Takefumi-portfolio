## 2. `/ja` の TBT（CI で 281ms／上限200ms）— Phase 4 の最初のタスク
上限は**緩めない**。このサイトは「性能改善エンジニア」の実績そのものなので、ここで妥協しない。次の順で対策し、各段階で CI の値を記録する。

1. **根拠ドロワーの中身を、本体の HTML から外す**
   - 各根拠を独立した静的ページ `/[locale]/evidence/[id]` にする。JS がなくても普通のリンクとして開ける（JS なしでも使えるという要件を維持）。
   - JS があるときは、クリックでそのページの中身を取得してダイアログに表示する。ホバー・フォーカス時に先読みする。
   - 既存の `#evidence-<id>` のURLは、小さなスクリプトで新しい動きにつなぐ（共有済みのURLを壊さない）。
   - 「根拠ごとに固有のURLがある」ことは、コンセプトをむしろ強める。
2. **画面外の地層のレイアウトを省く**：地層の `<section>` に `content-visibility: auto` を付け、`contain-intrinsic-size` を CSS で確定済みの高さ（`--layer-length`）と完全に一致させる。高さが確定しているので、レイアウトのずれは原理的に起きない。CLS 0 を維持していることを確認すること。
3. **日本語固有のコストを確認する**：ローカルでは言語差がノイズに見えたが、CI では `/ja` だけが上限を超えている。日本語の改行処理やフォントの扱いによるレイアウト時間の差を、CI に近い条件で測って報告する。
4. 1〜3で足りなければ、ハイドレーションの範囲を減らす。

合格条件：CI の Lighthouse（3回の中央値）で、`/ja` と `/en` の両方が TBT 200ms 以下、CLS 0、Accessibility 100。

## 3. 3D基盤チャンクの評価（約220ms）
- **受け入れる。** Web Worker への移行（大規模な作り直し）は行わない。ただし次の2つを条件にする。
  1. **最初の操作そのものを遅くしない**：3D の読み込みと評価は、操作に対する画面の更新（次の描画）が終わってから始める（例：`scheduler.postTask` の background 優先度、または次のフレームの後に予約する）。テスト用のビルドで、最初の操作の INP を計測して記録する。
  2. **ダウンロードとコンパイルを前倒しする**：読み込み後のアイドル時間に 3D 基盤チャンクを `modulepreload` などで先読みし、メインスレッドで行うのが評価だけになるようにする。これで TBT が増えないことを CI で確認する。
- 最終的な判断は、Phase 6 の iPhone 確認で行う。

## 5. Vercel プレビュー環境（オーナー承認済み）

### 前提（Hobby プランの仕様）
- Vercel 認証の Standard Protection で守られるのは、プレビューと各デプロイ固有のURL。**本番のドメイン（`<プロジェクト名>.vercel.app`）は誰でも見られる。**
- 新しいプロジェクトの最初のデプロイは本番扱いになる。

### 方針
- **本番のブランチを、まだ存在しない `release` にする。** `main` も `feat/*` も、push はすべてプレビュー（保護あり）になる。
- 最初の本番デプロイ（`main` の現状）が公開URLに出ることは避けられないので、次の2つで見つかりにくくする：
  - プロジェクト名を推測されにくいものにする（オーナーが取り込み時に設定）
  - 公開する日まで、全ページに `X-Robots-Tag: noindex` を付ける（検索エンジンに載せない）
- 中身は守秘チェックを通過済みの、本人のポートフォリオなので、見られても情報漏えいにはならない。

### Claude Code の作業（オーナーが Vercel に取り込む**前に**行う）
1. 全レスポンスに `X-Robots-Tag: noindex, nofollow` を付ける。環境変数 `SITE_LAUNCHED=true` のときだけ外す（Phase 7 で設定する）。
2. `/lab/*` は、ローカル開発と Vercel のプレビュー（`VERCEL_ENV=preview`）でだけ有効にする。本番のビルドには含めない現状を維持する。
3. Vercel 上でビルドが通ることを確認する（Node のバージョン指定、ビルドコマンド、性能チェック用の依存がビルドを壊さないか）。
4. `docs/VERCEL_SETUP.md` に、オーナー向けの設定手順と、環境ごとの環境変数の一覧を書く。
5. ここまでを push したら、オーナーに「取り込んでよい」と伝える。

### 取り込み後の確認（Claude Code）
- `feat/*` に小さな変更を push してプレビューが作られること、シークレットウィンドウで開くと Vercel のログイン画面になること、`X-Robots-Tag` が付いていることを確認し、WORKLOG に記録する。
