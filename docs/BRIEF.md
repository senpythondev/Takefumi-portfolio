## 3. コアコンセプト：GROUND TRUTH ／ 原典

> 「主張」は地表にある。「根拠」は地下にある。

- **スクロール ＝ 地下へ掘り進むこと ＝ 根本原因（Root Cause）へ近づくこと。**
- 地層は**新しいものほど上**にある（地質学と同じ）。最新の仕事が地表近く、最深部の岩盤はヘルシンキでの原点と信条。
- 各案件は1枚の**地層**であり、それぞれが固有の小さな世界（インタラクティブなシーン）になっている。
- **ボーリングコア・ナビゲーター（独自要素）：** 画面右端に3Dの円柱コアサンプルを置く。地層を通過するたびに、その案件の色のリングがコアに積み重なる。最後まで掘ると、訪問者の手元に「このエンジニアのキャリアそのもの」のコアサンプルが完成する。リングをクリックするとその地層へジャンプ（急ぐエージェント向けの近道）。
- **根拠ドロワー（独自要素）：** サイト上の**すべての数字がクリック可能**。開くと「何を・どう測ったか」「グラフ／テスト結果／再現ログ」「確度ラベル」を表示する。
  - 確度ラベル：`実測`（本番データ・テストで確認）／`概算`（当時の計測に基づく約値）／`再現`（守秘のため再現環境で作り直したもの）
  - 「確定事項と推測を明示的に分離する」というこの人の仕事の流儀を、サイトの仕組みそのもので体現する。

### 2. Genten（原典）— 唯一の「本物に触れる」地層
- 実サイト `https://genten.vercel.app/` を埋め込み、または大きなCTAで誘導（iframeが不可ならスクリーンショット＋リンク）。
- 3D／2D：35件の検証済みルールを**時系列のレーン**として描く（有効期間が途切れも重なりもなく連なる様子。版が切り替わる継ぎ目が光る）。
- フック（記事の主張）：「英語の解説は600万円と言う。金融庁は1,800万円と言う。」— 古い・誤った英語情報と、日本語の公式原典とのズレを冒頭で見せる。
  - 扱い：成果の数値ではないので `Metric` にも確度ラベルにもしない。**出典つきの引用**（`Citation`：出典＝本人のDEV記事へのリンク、記事内で示している根拠＝金融庁）として表示する。
- インタラクション：「25問レース」— **3構成**が同じ25問を1問ずつ解いていく（データ：`docs/facts/genten-eval.json`、`実測`）。
  - モデル単体（検索なし）：19/25（76%）
  - 同じ57ファイルへのキーワード検索（BM25）：18/25（72%）
  - Genten（Sanityナレッジベース＋MCP）：25/25（100%）
  - **物語の核：検索を足しただけでは、むしろ正答率が下がった（76% → 72%）。** キーワード検索は第8・12・13問でつまずき、第14〜16問と第19問では2つの比較構成がそろって誤答する。Gentenは1問も落とさない。
  - レース後に2つ目の指標へ切り替える：「正答し、かつ公式の出典を示せた」割合 — 8%／20%／100%。
  - 正直な代償も見せる：平均応答時間は 3.2秒／3.4秒／約15秒。Gentenは遅い → 改善計画（応答時間の短縮）へつなぐ。
  - ⚠ 設問の内容は受領していないので、各問の題材は表示しない（問番号と正誤だけ）。
- 失敗の演出：開発の途中で、Webページだけのナレッジベースが出典のない上限額を自分で計算し、**桁ずれを起こした**（4回）場面をグリッチ表現で見せ、構造化ルールへの切替で安定する。⚠ これは開発中の発見であり、25問評価の結果とは**別の出来事**。両者を混ぜて表現しない。

### 4. レガシーPHPセキュリティ診断 — 最も映画的な地層
- ⚠ **実コード・実ログ・URL・事業者を特定できる情報は一切出さない。** 演出はすべて「再現」ラベル付きの模擬データ。
- 3D：PHPファイル約45,000本を**都市**として描く（InstancedMeshで1ファイル＝1棟。高さ＝ファイルサイズ）。10年以上の増築で無秩序になった街並み。
- 探偵パート（インタラクション）：アクセスログの「応答サイズ」を波形として表示。訪問者がスライダーで閾値を動かすと、**わずかなサイズ差**が浮かび上がり、街の中の特定の区画にカメラが急降下していく → 不正設置ファイルが赤く脈打つ。
- リスクの可視化：拡張子検証のないアップロード、Cookie依存の認証、SQLインジェクション、パスワードの平文保存 — それぞれを街の「ひび割れ」「開いた扉」として映画的に表現する（グロテスクではなく、緊張感で見せる）。
- 収束：既存ファイルは無変更のまま無害化 → HTTPレスポンスで1件ずつ検証 → SHA-256ハッシュで証拠を「封印」（ハッシュ文字列が結晶化する演出）。
- 報告書の思想：画面を「確定」（白）と「推測」（琥珀）の2色に分けて表示する。
- 改善計画：緊急度順の4段階を地層のように積み上げて見せる。

### 5. ライブオークションAWS改善 — 体験型シミュレーション
- インタラクション：訪問者が**「同時入札者数」スライダー**を動かす。上げるほどCPUコアの温度色が上がり、ある点で瞬間的に飽和 → ネットワークエラーの破片が飛び散る。
- 判断の演出：「インスタンスを闇雲に増やす」ボタンはグレーアウトし、「まず実測する」を選ばせる（根拠のない増強を避けた判断の再現）。2秒ごとの監視グラフが流れる。
- 解決：汎用インスタンス → コンピューティング最適化（8コア）への移行と、php-fpm同時処理数のチューニング → 同じ負荷でも余裕が生まれる。
- 決着：本番オークション約6時間・約10,000件のカウンターが回り、「ネットワークエラー 0／タイムアウト 0／サーバーエラー 0」で止まる。
- 補足：本番から完全分離した低コストの検証環境（RDS・ElastiCache・ALB・最小権限IAM）を構成図で。

- **体験（目玉）：** 訪問者が名前を入力すると、その場で**本人の名前と現在時刻の透かしが入ったサンプルPDF**がプレビュー生成される（クライアント側生成。データは送信しない。サンプル文書はダミー）。「流出しても追跡できる」設計を一瞬で理解させる。

## 7. ビジュアル方針（初期案。デザインシステム確定時に更新）

- **ベース：** 温かみのある黒（地中の暗さ）。地層ごとに固有の色と質感を持つが、彩度は抑えて全体を統一する。
- **信号色：** 根拠＝冷たいシアン系、危機＝赤橙、収束＝落ち着いた緑。ネオン多用・サイバーパンクの定番表現は避ける。
- **書体：** 日本語本文は可読性の高いゴシック、見出しに個性のある書体を1つ、数字とデータは等幅。日本語フォントは重いため、サブセット化とウェイト数の制限を必須とする。
- **動き：** 物理的な重さを感じる動き（地層の圧力、掘削の抵抗感）。速いだけのフェード・スライドの多用は避ける。
