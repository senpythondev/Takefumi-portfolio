## 4. 3D基盤チャンクが250KBを超える見込み（254.2KB）

## 8. 実機検証の方針変更（重要）
オーナーは検証用のスマートフォンを自由に使えない。そこで、**開発中は実機に頼らない**方針に変える（PM_REVIEW_01 D10、PM_REVIEW_02 §8 を置き換える）。

1. **モバイルは「安全側」を既定にする**：タッチ端末では、重いシーン（特に都市）を既定で medium 以下で始め、実行中に fps が十分だと分かったときだけ段階を上げる。上げるときも下げるときも、`PerformanceMonitor` による自動調整に任せる。
2. **どんな端末でも壊れない**ことを最優先の合格条件にする：低性能の端末では、演出が控えめになるだけで、内容はすべて読めること。
3. **代わりの計測**：Chrome の CPU スロットリング（4倍と6倍）とモバイルのエミュレーションで計測し、合格基準は「6倍スロットリングで、都市を含む全シーンが25fps以上、または自動で降格して破綻しないこと」とする。Safari 固有の挙動は Playwright の WebKit で確認する。WORKLOG には「代わりの計測」と明記する。
4. **公開前に1回だけ**、実機の iPhone で通しの確認をする（オーナーの端末、またはクラウドの実機テストサービス）。この確認は Phase 6 に置き、`?debug=1` のHUDはそのために残す。
