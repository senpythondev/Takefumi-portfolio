# PMレビュー #04 — オーナーの決定：最寄駅の記述と拒否リストを取りやめる

> オーナーの決定（2026-11-18）。PM_REVIEW_02 §3 と PM_REVIEW_03 §2〜3 をこのレビューで置き換える。

## 1. 最寄駅・居住地の情報はどこにも書かない
- サイトにもドキュメントにも、最寄駅・路線・居住地に関する記述を一切置かない（「載せない」というルールの説明も含めて削除した）。
- サイトに載せる個人情報は **名前・メール・GitHub・DEV だけ**。BRIEF・CLAUDE.md・ASSET_CHECKLIST・サブエージェントの定義を、この表現に修正した。
- Claude Code の作業：
  - リポジトリ内のファイル（WORKLOG、スキャナのコード、テスト、コメントを含む）に、最寄駅・居住地に関する記述や値が残っていないか確認し、あれば削除する
  - `git log -p` の全履歴も確認し、もし残っていれば報告する（履歴の書き換えはオーナーの承認を得てから）

## 2. 拒否リストは作らない
- 拒否リストに関する仕組み（ファイルの読み込み、リストがないときにビルド・pre-commit・CI を失敗させる処理、`DENYLIST` シークレットの手順、関連するドキュメントの記述）を**すべて削除**する。
- `npm run build` は拒否リストなしで通る状態に戻す。
- 守秘はこれまでどおり次の3つで守る：
  1. **コンテンツの出典の制限**：サイトの文章と数値は BRIEF と `docs/facts/` からしか作らず、そこには顧客名が含まれていない（ファクトチェックの検証で機械的に担保）
  2. **パターンによるスキャナ**：IPアドレス、AWSのID・ARN、許可リストにないURL・メールアドレス、画像のEXIF
  3. **`confidentiality-guard`**：コミット前に、固有名詞やスクリーンショットの写り込みなど、パターンでは拾えないものを文脈で確認する

## 3. このあとの流れ
1. `docs/_agents/*.md` を `.claude/agents/` に配置する（PM_REVIEW_03 §1）
2. 上の1〜2を反映する
3. `confidentiality-guard` で全体（既存のコミットを含む）を確認する
4. Phase 2 をコミットし、PM_REVIEW_03 §7 の手順で GitHub に push する
5. Phase 3 に進む
