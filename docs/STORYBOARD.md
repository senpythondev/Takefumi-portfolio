## 0.1 参考サイトから取り入れる5つの原則

1. **主役の物体が1つあり、スクロールに合わせて形を変え続ける**（Apple、Blendr）→ 主役は**ボーリングコア**。引き上げられ、分解され、各帯が世界へ拡大し、最後に組み上がる。
2. **全画面のシーンを固定し、スクロールで再生する**（Apple、Sixfold）→ 各幕はスクロール量に対応したタイムラインで、スクロールを戻せば逆再生される。
3. **カメラが世界の中を移動し、場面に切れ目がない**（Active Theory、Sixfold）→ ページ遷移のような区切りを作らない。案件から案件へも、カメラの移動でつなぐ。
4. **大きな文字が動きに合わせて現れ、文章は最小限**（Apple）→ 各シーンの文字は、1行の見出しと大きな数字2〜3個、それと「ケーススタディを読む →」だけ。
5. **映画的な光**（Active Theory）→ ブルーム、被写界深度、浮遊する塵の粒子、シアンの光源。high ティアで使う。

## 2. ショット表

### 第0幕 読み込み（ヒーローに統合）
- ヒーローの HTML（名前・見出し・チップ）は最初から表示する（LCP）。
- 3Dの準備中は、ヒーロー右側で**シアンのボアホールが地表から下へ掘り進む**演出を、そのまま読み込みの進み具合として使う。小さな深度計（例：「0m → 1,000m」）を添える。
- 準備ができたら、ボアホールが画面の下端まで届き、地層とジオードが灯る。ページを止める読み込み画面は作らない。

### 第1幕 地表 — コアの引き上げ（固定 200vh）
| スクロール | カメラ | 物体 | 文字 |
|---|---|---|---|
| 0–30% | ボアホールへゆっくり寄る | ジオードが脈打つように明るくなる | 見出しとチップが上へ流れて消える |
| 30–70% | わずかに上を向く | 地表のドリルが動き、**ボアホールからコアが引き上げられる**。地層の壁は暗く後退し、被写界深度でぼける | — |
| 70–100% | 正面に固定 | コアが回転して横倒しになり、画面いっぱいの大きさで静止する（core-lab.png の質感） | 大きな文字：「8年分の地層を、1本のコアに。」 |

### 第2幕 分解（固定 150vh）
| スクロール | 物体 | 文字 |
|---|---|---|
| 0–60% | Apple の分解図のように、**11本の帯が軸方向に離れて間隔が開く**。帯の境目から光が漏れる | 各帯の上に細い線が立ち上がり、年代と案件名の小さなラベルが付く（core-lab.png のホログラムの線） |
| 60–100% | 最新の帯（現在：AIトレーニング）が手前に回転してきて、切断面がカメラを向く | — |

### 第3幕 帯ごとの世界（各案件、固定 250〜300vh）
**すべての案件で共通の型：**
| スクロール | 内容 |
|---|---|
| a. 入場 0–20% | カメラが帯の切断面に近づく。**切断面が画面いっぱいまで拡大**し、断面の縞模様が溶けて、その案件の世界に変わる（「拡大」の演出） |
| b. 問題 20–45% | その案件が抱えていた問題を、世界の中の出来事として見せる |
| c. 調査と判断 45–70% | 原因を特定する過程を見せる（「実測してから動く」） |
| d. 結果 70–90% | 大きな数字を画面中央に固定表示する（確度の記号付き） |
| e. 帰還 90–100% | カメラが引き、世界が縮んで帯の切断面に戻る → コアが回転して次の帯へ |

文字は、1行の見出し＋大きな数字2〜3個＋「ケーススタディを読む →」だけにする。

**案件ごとの中身（b → c → d）：**
- **ライブオークション**：b＝8本のCPUコアの光の柱が涼しいシアンで並び、入札の光の粒が殺到して柱が赤熱し、エラーの破片が飛ぶ／c＝「闇雲に増やす」という選択肢が灰色に消え、2秒ごとの監視グラフの線が走り、原因（瞬間的なCPU飽和）が1点に収束する／d＝柱が冷え、「約10,000件・エラー0件」のカウンターで止まる
- **レガシーPHP診断**（city.png）：b＝約45,000棟の夜の都市の俯瞰／c＝応答サイズの波形が地平線を走り、ずれた1点からカメラが急降下する。赤い亀裂が通りを伝って広がる（訪問者のスライダーで進む）／d＝亀裂が封じられ、SHA-256のハッシュが結晶化する。**全編に「再現」ラベル**
- **Genten**：b＝「英語の解説は600万円」と「金融庁は1,800万円」の2つの数字がぶつかる／c＝3本の光のレーンを25問が流れ、キーワード検索のレーンが第8・12・13問でつまずく（76%／72%／100%）／d＝「正答し、かつ公式の出典を示せた割合：100%」
- **特許開示**：b＝NDA → SMS → 法人番号 → PDF の光の配管／c＝訪問者の名前で透かしが入る体験（既存の仕様）／d＝「登録上限1,000名を自動管理」「通常3か月以上の規模を2か月以内」
- **就労支援法人サイトの移行**：b＝古い街の中の214の光の粒子／c＝4系統の不規則な軌道が、301転送で1本の川に整列して新しい街へ流れ込む／d＝「停止時間20分」
- **現在：AIトレーニングプラットフォーム**：b＝真っ暗な地形（初見のコード）／c＝光の筋が広がって構造が浮かび上がる／d＝変更が2つのゲート（AI検証 → 人間レビュー）を通過して緑に灯る。プラットフォーム名は出さない

### 第4幕 深層 — 回転しながら流れるカード（固定 200vh。Active Theory の Work の動き）
- 残りの8案件を、**その帯から薄く切り出した岩の断面（研磨された板）**として3D空間に並べる。板の表面には、業界・期間・主な技術・数値が刻まれている。
- スクロールに合わせて、板が奥から手前へ流れてくる。近づくにつれて**回転しながら正面を向き**、文字が読める位置で一瞬止まるように減速し、通り過ぎると傾いて流れ去る。
- ポインターの動きに合わせて、板がわずかに傾く。板をクリックすると、その案件のケーススタディを開く。
- モバイルでは縦の流れにし、回転は控えめにする。

### 第5幕 キャッチアップ速度（100vh）
- 帯が次々と光り、それぞれの「どれだけ早く成果を出したか」を大きな数字で示す（約2日、約3週間、約1週間、2か月以内）。速度という独自の数値は作らない。

### 第6幕 岩盤（100vh）
- 3つの信条「実測してから動く」「確定と推測を分ける」「原典に当たる」が、岩盤に刻まれた文字として、明かりが当たる順に現れる。ヘルシンキ大学から、フィンランドと日本の開発現場へ。

### 第7幕 終幕（固定 150vh）
- コアが再び組み上がり、暗い保管台に置かれる（core-lab.png）。各帯の上に、その案件のホログラムが立ち上がる。
- 最後の**空の帯**だけが、ゆっくり脈打つ：「まだ掘っていない地層がある。次は、あなたの案件だ。」→ 参画条件と連絡先。

## 3. 仕組みの変更（CLAUDE.md より優先する。Claude Code が CLAUDE.md に反映すること）

1. **ホームはシネマティック・スクロールにする。** 長い説明文は、案件ごとのケーススタディページ `/[locale]/work/[id]` に移す。ケーススタディは根拠ページと同じく、HTML が本体で、JS がなくても読める。ホームの各シーンは、1行の見出し＋数字＋リンクだけ。
2. **3Dは、読み込みが終わったらすぐ準備を始める**（medium と high ティア）。最初の操作を待たない（PM_REVIEW_05 §3.1 の方式を置き換える）。準備中の様子は、第0幕のボアホールで見せる。
3. **予算の見直し：**
   - 維持：LCP 2.5秒以内、CLS 0.05以下、INP 200ms以内（実際の操作への反応）、デスクトップ60fps・モバイル30fps
   - ホームの TBT は**計測して報告するだけ**にし、合否の条件から外す。ケーススタディ・根拠ページ・static 版では、TBT 200ms 以内を維持する
   - 3D関連（基盤＋全シーン＋テクスチャ・モデル）は、圧縮後の合計1.5MB以内を目安にする。次の幕のアセットは先読みする
4. **ポストプロセス**（ブルーム、被写界深度）を high ティアで使う。medium では軽量版にする。
5. **static 版と reduced-motion 版**では、同じ物語を、各シーンのポスター画像と HTML で見せる。
6. 確度の記号（≈ ✓ ↺）は大きな数字にも小さく添え、ラベルの全文はケーススタディと根拠ページで示す。

## 4. 最初のマイルストーン（M1）
- **範囲：** 第0幕〜第2幕と、第3幕のライブオークション（入場の拡大から帰還まで）。完成品質で作る。
- **モバイル：** 同じ流れを縦画面向けに作る。コアは横倒しにせず縦のまま扱い、分解も縦方向にする。切断面の拡大は同じ。
- **合格条件：** オーナーがプレビューを自分のブラウザで見て、「参考サイトと同じ種類の体験だ」と感じること。あわせて、`?debug=1` で計測した fps を報告する。
- M1 の合格後に、残りの案件の世界と第4〜7幕を順に作る。
