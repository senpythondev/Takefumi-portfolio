# 素材チェックリスト（オーナーの作業）

> 素材は「顧客情報が含まれていなければ使える」前提で進める。ただし、**顧客情報には直接の名前だけでなく、それを特定できる手がかりも含まれる**。下の匿名化手順を通過したものだけを `public/media/` に入れる。
> 念のため、各案件の契約書・NDAに「実績として公表すること」についての条項がないかも一度確認しておくこと。

## A. 共通の匿名化手順（すべての素材に適用）

- [ ] 顧客名・サービス名・ロゴ・ドメインを消す（ブラウザのURLバー、タブ名、ページタイトル、フッターも含む）
- [ ] IPアドレス、ホスト名、AWSアカウントID、インスタンスID、ARN、S3バケット名を消す
- [ ] 実在の人名・メールアドレス・電話番号・会員データを消す（ダミーデータに差し替えて撮り直すのが最善）
- [ ] 画像のメタデータ（EXIF、作成者、位置情報）を削除する
- [ ] ファイル名にも顧客名を入れない
- [ ] 迷ったものは使わずにPMに相談する

## B. 案件別に集める素材

### Genten（本人の公開物 — 制約なし）
- [ ] 公開URL（https://genten.vercel.app/）が動いていることを確認
- [ ] DEVの記事URL
- [ ] 評価25問の結果（CSVで可：`問番号, 構成名, 正誤`）。比較した構成すべて（第3構成があればその正答率も）
- [ ] 桁ずれが起きた回答の例（スクリーンショットかテキスト）
- [ ] 画面のスクリーンショット（デスクトップ・モバイル）
- [ ] GitHubリポジトリ（公開してよければ）

### 就労支援法人サイト（pegasus-job.com）
- [ ] **掲載とリンクについて先方の了承を得る**（下の文例Cを参照）
- [ ] 新サイトのスクリーンショット（デスクトップ・モバイル）
- [ ] 旧サイトのスクリーンショット（手元になければ Wayback Machine で取得できるか確認）
- [ ] 移行当日のタイムライン（停止〜公開の20分の流れ）
- [ ] 可能なら移行前後の Lighthouse スコア
- [ ] アクセス解析の数値は**使わない**（先方の経営情報にあたるため）

### レガシーPHPセキュリティ診断
- [ ] 公開してよいのは**集計値だけ**（ファイル数・容量・構造の数・期間など、ファクトシートの範囲）
- [ ] 実際のログ・コード・報告書・スクリーンショットは**使わない**（サイトでは再現データで演出する）
- [ ] 報告書の「構成」（目次の構造、確定と推測の書き分け方）を、中身を伏せて説明できるようにメモしておく

### ライブオークションAWS改善
- [ ] 監視スクリプトの出力（2秒ごとの記録）があれば、**時刻と数値だけ**のCSVにして、ホスト名などを削除したもの
- [ ] 負荷テストの結果（同時接続数とCPU・応答の関係）
- [ ] 改修前後のインスタンス構成（インスタンスの系統とコア数だけ。IDは不要）
- [ ] 構成図は新しく描き起こす（実際のコンソール画面は使わない）

### 研究者向け特許開示システム
- [ ] 実績としての掲載可否を確認（文例Cを流用）
- [ ] ダミーデータで撮った管理画面・登録フローのスクリーンショット
- [ ] 透かしPDFの見本（ダミー文書で生成したもの）
- [ ] 全体フロー図（手描きのラフでよい。清書はこちらで行う）

### AIトレーニングプラットフォーム（現在）
- [ ] プラットフォームの規約・NDAで、**名称や業務内容を公表してよいか**を確認（不明なら名称は出さない前提で進める）
- [ ] 素材は使わない（汎用的な説明のみ）

## C. 掲載許可のお願い（文例）

```
いつもお世話になっております。
先日のWebサイト移行案件につきまして、私個人のポートフォリオサイトで制作実績としてご紹介させていただきたく、ご相談いたします。

掲載を予定している内容：
・案件の概要（サイト移行・リニューアル）と、私が担当した作業内容
・公開中のサイトのスクリーンショットと、サイトへのリンク
・停止時間などの作業上の数値（アクセス数などの経営に関わる情報は掲載いたしません）

掲載前に該当箇所をご確認いただくことも可能です。
ご都合が悪い場合は、名称を伏せた形でのみ掲載いたします。
ご検討のほど、よろしくお願いいたします。
```

- [ ] GitHub／DEV／LinkedIn などのURL

- [ ] ヘルシンキ時代の写真など、原点を示す素材（任意。岩盤の地層で使える）
